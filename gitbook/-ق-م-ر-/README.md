# قمر (Qamar): پلی برای داده‌های میان‌رشته‌ای

اگر تا به حال با پروژه‌هایی سر و کار داشته‌اید که در آن داده‌های زیستی با تحلیل‌های اقتصادی یا مدل‌های اقلیمی تلاقی پیدا می‌کنند، می‌دانید که بزرگ‌ترین دردسر، یکپارچه‌سازی فرمت‌های ناسازگار است. **قمر (Qamar)** دقیقاً برای حل همین معضل متولد شده است؛ ابزاری برای مدیریت، تبدیل و تحلیل داده‌های چندرشته‌ای که به جای درگیر کردن شما با پیچیدگی‌های زیرساختی، اجازه می‌دهد روی هسته پژوهش تمرکز کنید.

وب‌سایت رسمی: [qamar.website](https://qamar.website)

---

## چرا قمر؟ (فلسفه پروژه)

در دنیای امروز، مرزهای بین رشته‌ها کمرنگ شده است. ابزارهای سنتی معمولاً در «سیلوها» (Silos) محصور هستند. قمر به شما اجازه می‌دهد تا با استفاده از یک رابط یکپارچه، داده‌ها را از منابع مختلف (JSON, CSV, NetCDF, و حتی پایگاه‌داده‌های سری زمانی) فراخوانی کرده و یک «پایپ‌لاین» واحد برای آن‌ها تعریف کنید.

### ویژگی‌های کلیدی
*   **تطبیق‌پذیری بالا:** پشتیبانی از فرمت‌های داده‌ای سنگین علمی.
*   **سرعت:** بهینه‌شده برای پردازش‌های موازی.
*   **سادگی:** منحنی یادگیری بسیار نرم برای محققین.

## شروع سریع (نصب و راه‌اندازی)

نصب قمر به لطف پکیج‌منیجرهای مدرن، تنها چند ثانیه زمان می‌برد. اگر از پایتون استفاده می‌کنید، محیط مجازی خود را فعال کرده و دستور زیر را اجرا کنید:

```bash
# نصب پکیج اصلی
pip install qamar-core

# تأیید نصب
qamar --version
```

برای کاربرانی که به دنبال تحلیل‌های سنگین‌تر هستند، پیشنهاد می‌کنم از نسخه Docker استفاده کنید تا تمام وابستگی‌های سیستمی (Dependencies) به صورت ایزوله مدیریت شوند:

```bash
docker pull qamar/engine:latest
docker run -it qamar/engine --init
```

## نحوه استفاده: یک مثال کاربردی

فرض کنید می‌خواهید داده‌های دمایی (اقلیم‌شناسی) را با داده‌های بهره‌وری (اقتصادی) ترکیب کنید. قمر این کار را با متد `merge_layers` به سادگی انجام می‌دهد.

```python
import qamar

# بارگذاری منابع داده
climate_data = qamar.load("climate_report.nc")
econ_data = qamar.load("market_trends.csv")

# ترکیب و نرمال‌سازی داده‌ها
integrated_set = qamar.merge_layers(
    source=[climate_data, econ_data],
    key="timestamp",
    strategy="interpolate"
)

# خروجی گرفتن برای تحلیل
integrated_set.export("analysis_ready.json")
```

## جدول مقایسه‌ای: قمر در برابر روش‌های سنتی

| قابلیت | روش‌های سنتی (Excel/Scripts) | قمر (Qamar) |
| :--- | :--- | :--- |
| **یکپارچه‌سازی** | دستی و مستعد خطا | خودکار و بر اساس Schema |
| **مقیاس‌پذیری** | محدود به RAM | توزیع‌شده (Distributed) |
| **تکرارپذیری** | پایین | بسیار بالا (Pipeline-based) |
| **انعطاف رشته‌ای** | بسیار سخت | بومی (Native Support) |

## سوالات متداول (FAQ)

**۱. آیا قمر برای پروژه‌های کوچک دانشجویی مناسب است؟**
قطعاً. با وجود اینکه برای تحلیل‌های کلان‌داده طراحی شده، اما در پروژه‌های کوچک هم باعث صرفه‌جویی زمان در مرتب‌سازی داده‌ها می‌شود.

**۲. آیا می‌توانم فیلترهای شخصی‌سازی شده بنویسم؟**
بله، قمر از افزونه‌های پایتونی پشتیبانی می‌کند. می‌توانید کلاس‌های `BaseFilter` را ارث‌بری کرده و منطق اختصاصی خود را اضافه کنید.

**۳. پشتیبانی از داده‌های حجیم (Big Data) چگونه است؟**
قمر از مکانیزم `Lazy Loading` استفاده می‌کند؛ یعنی داده‌ها تا زمانی که واقعاً نیاز نباشند در حافظه بارگذاری نمی‌شوند. این یعنی حتی با سیستم‌های معمولی هم می‌توانید با فایل‌های چندین گیگابایتی کار کنید.
