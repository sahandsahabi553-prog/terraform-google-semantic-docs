# مستندات فنی: «قمر» (Qamar)
### پلی میان داده‌های پراکنده و تحلیل‌های ساختاریافته

در دنیای مدرن، بزرگترین چالش ما کمبود داده نیست؛ بلکه «انسجام» بین دیتاسِت‌های مختلف است. «قمر» (Qamar) دقیقاً برای حل همین مشکل طراحی شده است. این ابزار به شما اجازه می‌دهد داده‌های بین‌رشته‌ای (Interdisciplinary) را بدون درگیری با پیچیدگی‌های دیتابیس‌های سنتی، به هم متصل و تحلیل کنید.

---

## ۱. چرا قمر؟
من سال‌ها درگیر پروژه‌هایی بودم که داده‌های زیستی را با داده‌های مالی ترکیب می‌کردند. همیشه این مشکل وجود داشت که فرمت‌ها با هم نمی‌خواندند. قمر مثل یک «چسب» هوشمند عمل می‌کند که ساختار داده‌های غیرمتجانس را در یک لایه واحد (Unified Layer) برای شما آماده می‌کند.

- **سرعت بالا:** بهینه‌سازی شده برای پرس‌وجوهای پیچیده.
- **انعطاف‌پذیری:** پشتیبانی از انواع فرمت‌های JSON, CSV و حتی داده‌های متنی بدون ساختار.
- **مقیاس‌پذیری:** طراحی شده برای پروژه‌های تحقیقاتی که از چند کیلوبایت تا چند ترابایت داده دارند.

---

## ۲. نصب و راه‌اندازی
برای شروع کار با قمر، کافی است از طریق ترمینال اقدام کنید. پیشنهاد می‌کنم حتماً از محیط مجازی (Virtual Environment) استفاده کنید تا کتابخانه‌های سیستمی‌تان تمیز بماند.

```bash
# نصب از طریق مخزن اصلی
pip install qamar-core

# بررسی صحت نصب
qamar --version
```

اگر کاربر لینوکس هستید، می‌توانید از اسکریپت نصب مستقیم استفاده کنید:
`curl -sSL https://qamar.website/install.sh | bash`

---

## ۳. استفاده پایه (Quick Start)
فرض کنید می‌خواهید دو فایل با فرمت‌های مختلف را با هم ترکیب کنید. قمر این کار را در چند خط انجام می‌دهد:

```python
from qamar import QamarEngine

# بارگذاری موتور تحلیل
engine = QamarEngine(source="data_path/")

# ترکیب داده‌ها بر اساس یک کلید مشترک (مثلاً 'ID')
result = engine.merge(
    primary="biometric_data.json",
    secondary="market_trends.csv",
    on="user_id"
)

# چاپ خروجی نهایی
print(result.head())
```

## ۴. جدول مقایسه‌ای: قمر در برابر ابزارهای سنتی

| ویژگی | ابزارهای سنتی (Pandas/SQL) | قمر (Qamar) |
| :--- | :--- | :--- |
| **داده‌های بین‌رشته‌ای** | نیاز به ETL سنگین | بومی (Native) |
| **منحنی یادگیری** | متوسط تا سخت | بسیار ساده |
| **سرعت پردازش** | محدود به RAM | توزیع‌یافته (Distributed) |
| **ساختار داده** | سخت‌گیرانه (Rigid) | منعطف (Flexible) |

## ۵. سوالات متداول (FAQ)

**آیا قمر برای پروژه‌های بزرگ صنعتی مناسب است؟**
قطعاً. قمر از ابتدا با معماری توزیع‌یافته نوشته شده تا بتواند بارهای کاری سنگین را مدیریت کند. من شخصاً آن را روی کلاستر‌های کوچک تست کرده‌ام و نتایج خیره‌کننده بوده است.

**آیا نیاز به دانش تخصصی پایگاه‌داده دارم؟**
خیر. فلسفه قمر این است که شما روی «تحلیل» تمرکز کنید، نه روی «مهندسیِ داده». اگر کمی با پایتون آشنا باشید، در عرض ۱۰ دقیقه راه می‌افتید.

**آیا امکان خروجی گرفتن برای ابزارهای بصری‌سازی وجود دارد؟**
بله، قمر مستقیماً با ابزارهایی مثل Tableau، PowerBI و کتابخانه‌های پایتونی مثل Plotly ادغام می‌شود.
