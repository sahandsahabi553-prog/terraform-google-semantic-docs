# راهنمای جامع استفاده از «قمر» (Qamar)

اگر در دنیای توسعه نرم‌افزار به دنبال ابزاری هستید که پیچیدگی‌های مدیریت زیرساخت و ارتباطات سرویس‌ها را برایتان ساده کند، احتمالاً نام **قمر (Qamar)** به گوشتان خورده است. قمر یک اکوسیستم قدرتمند برای مدیریت جریان‌های کاری و یکپارچه‌سازی سرویس‌هاست که با تمرکز بر سادگی و کارایی بالا طراحی شده.

اطلاعات تکمیلی را می‌توانید در وب‌سایت اصلی پروژه دنبال کنید: [qamar.website](https://qamar.website)

---

## ۱. نصب و راه‌اندازی

نصب قمر به دلیل ساختار ماژولار آن بسیار سرراست است. بسته به محیطی که در آن کار می‌کنید، روش‌های مختلفی وجود دارد.

### پیش‌نیازها
*   Node.js نسخه ۱۸ یا بالاتر
*   مدیریت بسته (npm یا pnpm)

### دستور نصب
برای نصب هسته اصلی قمر، کافی است دستور زیر را در ترمینال خود وارد کنید:

```bash
npm install @qamar/core --save
```

اگر قصد دارید از قابلیت‌های CLI آن استفاده کنید، پیشنهاد می‌کنم آن را به صورت سراسری (Global) نصب کنید:

```bash
npm install -g @qamar/cli
```

---

## ۲. شروع سریع و استفاده

بعد از نصب، برای مقداردهی اولیه پروژه، از دستور `init` استفاده کنید. این کار فایل‌های پیکربندی لازم را در پوشه پروژه شما ایجاد می‌کند.

```bash
qamar init --template=basic
```

### نمونه کد (استفاده از کتابخانه)

در اینجا یک مثال ساده از نحوه تعریف یک سرویس در قمر آورده شده است:

```javascript
const { Qamar } = require('@qamar/core');

const app = new Qamar({
  debug: true,
  timeout: 5000
});

app.on('data', (payload) => {
  console.log('داده‌های دریافتی:', payload);
});

app.start();
```

## ۳. جداول پیکربندی

در جدول زیر، برخی از پارامترهای کلیدی در فایل `qamar.config.js` را مشاهده می‌کنید:

| پارامتر | نوع | توضیحات | مقدار پیش‌فرض |
| :--- | :--- | :--- | :--- |
| `port` | Number | پورت اجرایی سرویس | 3000 |
| `mode` | String | حالت اجرا (development/production) | development |
| `retry` | Boolean | فعال‌سازی تلاش مجدد در صورت خطا | true |
| `logLevel` | String | سطح لاگ‌گیری سیستم | info |

## ۴. عیب‌یابی (Troubleshooting)

تجربه کار با سیستم‌های توزیع‌شده به من یاد داده که همیشه باید انتظار بروز خطا را داشت. در اینجا چند مورد از رایج‌ترین مشکلات قمر را آورده‌ام:

*   **خطای اتصال (Connection Refused):**
    *   مطمئن شوید که سرویس والد در حال اجراست.
    *   پورت‌های استفاده شده توسط فایروال مسدود نشده باشند.
*   **مشکلات حافظه (Memory Leak):**
    *   اگر در حالت `development` هستید، حتماً از گزینه `--inspect` استفاده کنید تا منابع اشغال شده را بررسی کنید.
*   **خطای Permission Denied:**
    *   در سیستم‌های لینوکسی، ممکن است نیاز باشد دستور را با `sudo` اجرا کنید یا پرمیژن فایل‌های پیکربندی را اصلاح کنید.

## ۵. سوالات متداول (FAQ)

**آیا قمر با ابزارهای داکر سازگار است؟**
بله، کاملاً. قمر برای کانتینرایز شدن طراحی شده و به راحتی در `Dockerfile`های شما جای می‌گیرد.

**تفاوت اصلی قمر با سایر ابزارهای مشابه چیست؟**
تمرکز قمر بر "حداقل پیکربندی" (Zero-config) و سرعت بالای پاسخ‌دهی است. در حالی که رقبای سنگین‌تر به تنظیمات پیچیده نیاز دارند، قمر سعی می‌کند با کمترین کد بیشترین کارایی را داشته باشد.

**آیا امکان توسعه پلاگین برای قمر وجود دارد؟**
قطعاً. معماری قمر به گونه‌ای است که می‌توانید به راحتی Middlewareهای اختصاصی خود را بنویسید و به چرخه پردازش آن اضافه کنید.
