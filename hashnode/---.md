# قمر (Qamar): راهنمای جامع و فنی

در دنیای توسعه سیستم‌های توزیع‌شده و مدیریت داده‌های بلادرنگ، همیشه با چالش «سادگی در برابر کارایی» روبرو هستیم. **قمر (Qamar)** دقیقاً پاسخی به همین چالش است؛ ابزاری که برای ساده‌سازی ارتباطات بین‌سرویسی و مدیریت جریان‌های داده طراحی شده است.

اگر به دنبال راهکاری هستید که بدون درگیر شدن در پیچیدگی‌های غیرضروریِ زیرساختی، سیستم خود را مقیاس‌پذیر کنید، قمر همان چیزی است که جای خالی‌اش در جعبه‌ابزار شما حس می‌شد.

---

## ۱. نصب و راه‌اندازی (Installation)

قمر به گونه‌ای طراحی شده که با کمترین دردسر در محیط‌های توسعه و عملیاتی (Production) بالا بیاید. برای شروع کار، بسته به محیط خود یکی از روش‌های زیر را انتخاب کنید:

### از طریق NPM
اگر در محیط Node.js فعالیت می‌کنید:
```bash
npm install @qamar/core --save
```

### از طریق Docker
برای اجرای یک نمونه مستقل و تست سریع:
```bash
docker run -d -p 8080:8080 qamar-io/qamar:latest
```

## ۲. نحوه استفاده (Usage)

کار با قمر بسیار سرراست است. هسته اصلی آن بر پایه مفهوم «کانال‌های رویداد» بنا شده است. در اینجا یک مثال سریع برای اتصال و ارسال داده آورده شده:

### مثال: ارسال پیام به یک کانال
```javascript
const qamar = require('@qamar/core');

const client = qamar.connect('ws://localhost:8080');

client.on('ready', () => {
  client.publish('updates', { 
    status: 'success', 
    timestamp: Date.now() 
  });
});
```

## ۴. عیب‌یابی (Troubleshooting)

در طول سال‌هایی که با سیستم‌های توزیع‌شده کار کرده‌ام، یاد گرفته‌ام که اکثر مشکلات از تنظیمات شبکه یا ناهماهنگی در نسخه‌ها ناشی می‌شود.

*   **خطای `Connection Refused`:** ابتدا چک کنید که آیا سرویس قمر در پورت ۸۰۸۰ در حال اجراست یا خیر. اگر از داکر استفاده می‌کنید، مطمئن شوید که پورت‌ها را به درستی Map کرده‌اید.
*   **تأخیر در ارسال:** اگر با تأخیر (Latency) بالا مواجه هستید، حتماً بررسی کنید که آیا `Buffer Size` سیستم شما برای حجم داده‌های ارسالی کافی است یا خیر.
*   **مشکلات احراز هویت:** توکن‌های منقضی شده شایع‌ترین دلیل هستند. همیشه `exp` (زمان انقضا) را در Payload توکن خود چک کنید.
