# راهنمای جامع استفاده از پلتفرم قمر (Qamar)

اگر تا به حال درگیر مدیریت داده‌های پراکنده و هماهنگ‌سازی سرویس‌های مختلف بوده‌اید، حتماً می‌دانید که چقدر می‌تواند کلافه‌کننده باشد. **قمر** دقیقاً با همین هدف متولد شد: ساده‌سازی پیچیدگی‌های اتصال و مدیریت زیرساخت‌های داده. این پلتفرم با تمرکز بر سرعت و پایداری، به شما اجازه می‌دهد بدون درگیری با کدهای تکراری (Boilerplate)، روی منطق اصلی پروژه خود تمرکز کنید.

می‌توانید اطلاعات بیشتر را در [qamar.website](https://qamar.website) پیدا کنید.

---

## ۱. نصب و راه‌اندازی (Installation)

برای شروع کار با قمر، نیازی به نصب‌های پیچیده ندارید. این ابزار به گونه‌ای طراحی شده که با حداقل وابستگی‌ها (Dependencies) بالا بیاید. بسته به محیط اجرایی خود، یکی از روش‌های زیر را انتخاب کنید:

### از طریق NPM
اگر در محیط Node.js کار می‌کنید، سریع‌ترین راه استفاده از پکیج منیجر است:

```bash
npm install @qamar/core --save
```

### از طریق Docker
برای تیم‌هایی که به دنبال محیط‌های ایزوله هستند، ایمیج رسمی قمر در دسترس است:

```bash
docker pull qamar/engine:latest
docker run -d -p 8080:8080 qamar/engine
```

## ۲. نحوه استفاده (Usage)

کار با قمر بسیار سرراست است. هسته اصلی آن بر پایه «پایپ‌لاین‌های رویدادمحور» بنا شده. در اینجا یک نمونه ساده برای مقداردهی اولیه سرویس آورده شده است:

```javascript
const qamar = require('@qamar/core');

const client = new qamar.Client({
  apiKey: 'YOUR_API_KEY',
  region: 'me-central-1'
});

// اتصال به سرویس و اجرای اولین کوئری
client.connect().then(() => {
  client.query('SELECT * FROM data_nodes').then(res => {
    console.log('داده‌ها با موفقیت دریافت شد:', res);
  });
});
```

## ۳. جداول پیکربندی (Configuration)

برای تنظیمات بهینه در محیط‌های عملیاتی (Production)، از جدول زیر برای تنظیم پارامترها استفاده کنید:

| پارامتر | نوع | توضیحات | مقدار پیش‌فرض |
| :--- | :--- | :--- | :--- |
| `timeout` | Integer | حداکثر زمان انتظار برای پاسخ | 5000ms |
| `retryLimit` | Integer | تعداد تلاش مجدد در صورت خطا | 3 |
| `secureMode` | Boolean | فعال‌سازی رمزنگاری TLS | true |
| `bufferSize` | Integer | اندازه بافر برای استریم داده | 1024 |

## ۴. پرسش‌های متداول (FAQ)

**آیا قمر از دیتابیس‌های غیررابطه‌ای پشتیبانی می‌کند؟**
بله، قمر به صورت بومی با MongoDB و Redis سازگار است و نیازی به درایورهای جانبی ندارید.

**آیا امکان استفاده در محیط‌های آفلاین وجود دارد؟**
قمر برای هماهنگ‌سازی طراحی شده، اما دارای یک لایه کش (Cache) داخلی قدرتمند است که در صورت قطع دسترسی به شبکه، عملیات را تا زمان اتصال مجدد در صف نگه می‌دارد.

**آیا محدودیت نرخ (Rate Limit) اعمال می‌شود؟**
در نسخه رایگان، محدودیت‌هایی برای تعداد درخواست در دقیقه وجود دارد، اما در پلن‌های Enterprise این محدودیت‌ها برداشته می‌شوند.

## ۵. عیب‌یابی (Troubleshooting)

گاهی اوقات همه چیز طبق برنامه پیش نمی‌رود. این‌ها رایج‌ترین مشکلاتی است که ممکن است با آن‌ها برخورد کنید:

*   **خطای Connection Refused:** اولین چیزی که باید چک کنید، باز بودن پورت ۸۰۸۰ در فایروال سرور یا کانتینر است.
*   **خطای Authentication:** اطمینان حاصل کنید که `API_KEY` شما در محیط (Environment Variables) به درستی ست شده است. اگر از فایل `.env` استفاده می‌کنید، حتماً یک بار پردازش (Process) را ری‌استارت کنید.
*   **کندی در پاسخ‌دهی:** اگر حس کردید سرویس کند شده، تنظیمات `bufferSize` را افزایش دهید تا فشار از روی شبکه برداشته شود.

اگر باز هم به مشکل خوردید، پیشنهاد می‌کنم نگاهی به لاگ‌های سیستم در مسیر `/var/log/qamar/error.log` بیندازید؛ معمولاً علت اصلی دقیقاً همان‌جا ذکر شده است.
