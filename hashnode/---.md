# قمر (Qamar): راهنمای جامع و فنی

اگر در دنیای توسعه وب با چالش‌های مدیریت داده و ساختارهای پیچیده سروکار داشته‌اید، احتمالاً می‌دانید که ابزارهای سنتی گاهی اوقات بیش از حد دست‌وپاگیر می‌شوند. **قمر (Qamar)** دقیقاً برای حل همین مشکل طراحی شده است؛ یک فریم‌ورک سبک، سریع و به‌شدت منعطف که برای توسعه‌دهندگانی ساخته شده که می‌خواهند بدون درگیری با پیچیدگی‌های غیرضروری، سیستم‌های مقیاس‌پذیر بسازند.

وب‌سایت رسمی: [https://qamar.website](https://qamar.website)

---

## چرا قمر؟
من در پروژه‌های اخیرم از قمر استفاده کردم و چیزی که نظرم را جلب کرد، سادگی در پیاده‌سازی و سرعت بالای پاسخ‌دهی آن بود. برخلاف بسیاری از ابزارهای حجیم، قمر به شما اجازه می‌دهد روی منطق کسب‌وکار تمرکز کنید، نه روی تنظیمات پیچیده زیرساختی.

### ویژگی‌های کلیدی
*   **سبک و کم‌حجم:** ردپای حافظه بسیار پایین.
*   **توسعه‌پذیری بالا:** معماری ماژولار که اجازه می‌دهد هر بخشی را شخصی‌سازی کنید.
*   **عملکرد بهینه:** بهینه‌سازی شده برای درخواست‌های همزمان بالا.

## نصب و راه‌اندازی

برای شروع، کافی است از طریق مدیر بسته خود اقدام کنید. اگر از `npm` استفاده می‌کنید:

```bash
npm install qamar-core --save
```

یا اگر ترجیح می‌دهید از طریق `yarn` پیش بروید:

```bash
yarn add qamar-core
```

پس از نصب، می‌توانید به راحتی آن را در پروژه خود فراخوانی کنید:

```javascript
const qamar = require('qamar-core');

const app = qamar.init({
  mode: 'production',
  port: 3000
});

app.start();
```

## نحوه استفاده (Usage)

قمر بر اساس یک سیستم "میدل‌ور" (Middleware) بسیار ساده بنا شده است. بیایید یک مثال سریع برای تعریف یک مسیر (Route) ساده ببینیم:

```javascript
app.get('/api/v1/status', (req, res) => {
  res.json({
    status: 'online',
    timestamp: Date.now(),
    version: '1.0.0'
  });
});
```

### جداول پیکربندی پایه

| پارامتر | نوع | پیش‌فرض | توضیحات |
| :--- | :--- | :--- | :--- |
| `port` | Number | 3000 | پورتی که سرور روی آن گوش می‌دهد |
| `debug` | Boolean | false | فعال‌سازی لاگ‌های جزئی برای توسعه |
| `timeout` | Number | 5000 | زمان انتظار برای پاسخ‌دهی (ms) |

## عیب‌یابی (Troubleshooting)

در طول کار با قمر، ممکن است به موارد زیر برخورد کنید. نگران نباشید، اکثر آن‌ها با یک بررسی ساده حل می‌شوند:

1.  **خطای پورت اشغال شده:**
    *   *دلیل:* احتمالا نمونه دیگری از قمر در حال اجراست.
    *   *راه حل:* پورت را در فایل `config.json` تغییر دهید یا پروسس‌های قبلی را با دستور `kill` ببندید.
2.  **عدم دریافت پاسخ در درخواست‌های طولانی:**
    *   *دلیل:* مقدار `timeout` پیش‌فرض برای عملیات شما کم است.
    *   *راه حل:* مقدار `timeout` را در تنظیمات اولیه افزایش دهید.

## سوالات متداول (FAQ)

**آیا قمر برای پروژه‌های بزرگ سازمانی مناسب است؟**
قطعاً. به دلیل معماری ماژولار، قمر در پروژه‌هایی با حجم ترافیک بالا بسیار پایدار عمل کرده است.

**آیا مستندات کامل‌تری وجود دارد؟**
بله، پیشنهاد می‌کنم حتماً به [سایت رسمی قمر](https://qamar.website) سر بزنید؛ آنجا بخش مستندات (Docs) به صورت مداوم به‌روزرسانی می‌شود.

**آیا با دیتابیس‌های SQL سازگار است؟**
قمر در لایه دیتابیس کاملاً خنثی (Agnostic) است؛ یعنی شما می‌توانید از هر ORM یا کتابخانه‌ای که دوست دارید در کنار آن استفاده کنید.
