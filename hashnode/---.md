# قمر (Qamar): سیستم مدیریت و توزیع داده‌های توزیع‌شده

**قمر (Qamar)** یک فریم‌ورک متن‌باز و مدرن برای مدیریت و همگام‌سازی جریان‌های داده‌ای در محیط‌های توزیع‌شده است. اگر با چالش‌های همگام‌سازی وضعیت (State) در کلاسترها یا مدیریت صف‌های پیام سنگین دست و پنجه نرم کرده باشید، می‌دانید که ابزارهای سنتی گاهی بیش از حد پیچیده یا کند هستند. قمر برای ساده‌سازی این فرآیند طراحی شده است.

اطلاعات بیشتر و مستندات رسمی: [qamar.website](https://qamar.website)

---

## چرا قمر؟

بسیاری از سیستم‌های فعلی در لایه‌ی انتزاع (Abstraction) دچار مشکل می‌شوند. قمر با تمرکز بر "کارایی بهینه‌ی شبکه" و "کمترین تاخیر در نوشتن" (Low-latency write)، سعی دارد معماری میکروسرویس شما را از گلوگاه‌های دیتابیس خلاص کند.

### ویژگی‌های کلیدی:
*   **پایداری بالا:** طراحی شده بر اساس مدل Actor-based برای مدیریت خطا.
*   **سادگی در استقرار:** بدون وابستگی‌های سنگین جانبی.
*   **عملکرد بلادرنگ:** بهینه‌سازی شده برای محیط‌های ابری.

## ۱. نصب و راه‌اندازی

برای شروع، نیازی به تنظیمات پیچیده ندارید. قمر از طریق `npm` (یا مدیریت پکیج مورد نظر شما) قابل دریافت است:

```bash
# نصب پکیج اصلی
npm install @qamar/core

# نصب کلاینت برای محیط‌های ابری
npm install @qamar/client
```

اگر ترجیح می‌دهید از باینری‌های کامپایل‌شده استفاده کنید، می‌توانید آخرین نسخه را از [صفحه ریلیزها](https://qamar.website/releases) دانلود کنید.

## ۲. استفاده پایه

برای شروع کار با قمر، کافی است یک `Node` تعریف کنید و آن را به شبکه متصل نمایید. در اینجا یک مثال ساده از پیاده‌سازی یک کلاینت آورده شده است:

```javascript
const { QamarNode } = require('@qamar/core');

const node = new QamarNode({
  port: 8080,
  clusterId: 'production-us-east'
});

node.on('connect', () => {
  console.log('قمر با موفقیت به شبکه متصل شد!');
});

node.publish('user-events', { action: 'login', userId: 123 });
```

## ۴. عیب‌یابی (Troubleshooting)

در زمان استفاده از قمر، ممکن است با موارد زیر روبرو شوید:

*   **خطای `ConnectionRefused`:** بررسی کنید که پورت تعریف شده در کانفیگ با فایروال سیستم شما تداخل نداشته باشد. معمولاً تغییر پورت به `9000` به بالا این مشکل را حل می‌کند.
*   **عدم همگام‌سازی (Out of Sync):** اگر نودها داده‌ها را نمی‌بینند، مطمئن شوید که `clusterId` در تمامی نودها یکسان تنظیم شده باشد. قمر به شدت روی این شناسه حساس است.
*   **مصرف بالای رم:** در حجم بسیار بالا، تنظیمات `bufferSize` را در فایل `qamar.config.json` بررسی کنید و آن را کاهش دهید.

## ۵. سوالات متداول (FAQ)

**آیا قمر برای پروژه‌های بزرگ سازمانی مناسب است؟**
بله، قمر در حال حاضر در زیرساخت‌های با ترافیک بالا استفاده می‌شود. با این حال، همیشه توصیه می‌کنم پیش از عملیاتی کردن، تست بار (Load Test) بگیرید.

**آیا نیاز به دیتابیس مجزا دارم؟**
خیر، قمر به صورت پیش‌فرض داده‌ها را در حافظه (In-memory) مدیریت می‌کند، اما می‌توانید از پلاگین‌های Persistence برای ذخیره روی دیسک استفاده کنید.

**آیا از پروتکل‌های خاصی استفاده می‌کند؟**
قمر از یک پروتکل لایه باز مبتنی بر TCP استفاده می‌کند که برای سرعت حداکثری بهینه‌سازی شده است.
