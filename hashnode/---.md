# راهنمای جامع استفاده از «قمر» (Qamar)

اگر تا به حال درگیر چالش‌های مدیریت سیستم‌های توزیع‌شده یا پیکربندی‌های پیچیده در محیط‌های عملیاتی بوده‌اید، احتمالاً می‌دانید که ابزارهای موجود اغلب یا بیش از حد سنگین هستند یا انعطاف‌پذیری لازم را ندارند. «قمر» (Qamar) پاسخی است به همین نیاز: یک راهکار هوشمند برای مدیریت و هماهنگ‌سازی سرویس‌ها که سادگی را با قدرتِ پردازشی بالا ترکیب کرده است.

اطلاعات بیشتر در وب‌سایت رسمی: [qamar.website](https://qamar.website)

---

## ۱. نصب و راه‌اندازی

نصب قمر بسیار سرراست است. ما سعی کردیم وابستگی‌ها را به حداقل برسانیم تا در هر محیطی، از سرورهای لینوکسی گرفته تا کانتینرهای داکر، بدون دردسر بالا بیاید.

### پیش‌نیازها
*   نسخه ۸ به بالای Node.js
*   دسترسی به پورت‌های استاندارد شبکه

### دستور نصب
سریع‌ترین راه، استفاده از `npm` است:

```bash
npm install -g @qamar/cli
```

اگر ترجیح می‌دهید از کد منبع استفاده کنید:

```bash
git clone https://github.com/qamar-project/qamar
cd qamar
npm install && npm run build
```

## ۲. شروع به کار (Usage)

بعد از نصب، اولین قدم مقداردهی اولیه محیط کاری است. قمر از فایل‌های پیکربندی با فرمت YAML استفاده می‌کند تا خوانایی بالایی داشته باشد.

### ایجاد پیکربندی اولیه
```bash
qamar init --project my-service
```

این دستور یک فایل `qamar.yaml` در پوشه شما ایجاد می‌کند. ساختار نمونه آن به این شکل است:

```yaml
service:
  name: "auth-gateway"
  port: 8080
  nodes:
    - host: "192.168.1.10"
      role: "primary"
    - host: "192.168.1.11"
      role: "replica"
```

### اجرای سرویس
برای بالا آوردن سرویس کافیست دستور زیر را اجرا کنید:

```bash
qamar start --config qamar.yaml
```

## ۳. قابلیت‌های کلیدی (در یک نگاه)

| قابلیت | شرح |
| :--- | :--- |
| **Failover** | تشخیص خودکار خرابی نودها و جایگزینی سریع |
| **Zero-Config** | شناسایی خودکار سرویس‌ها در شبکه محلی |
| **Log Aggregation** | جمع‌آوری متمرکز لاگ‌ها بدون نیاز به ابزارهای جانبی |
| **Security** | رمزنگاری داخلی تمامی ارتباطات بین‌نودی |

## ۴. عیب‌یابی (Troubleshooting)

حتی بهترین ابزارها هم گاهی اوقات در محیط‌های خاص به مشکل می‌خورند. اگر با خطایی مواجه شدید، این لیست را چک کنید:

*   **خطای اتصال (Connection Timeout):** معمولاً به دلیل بسته بودن پورت‌های فایروال است. مطمئن شوید پورت‌های مورد استفاده در `qamar.yaml` باز هستند.
*   **خطای همگام‌سازی (Sync Error):** بررسی کنید که ساعت سیستم‌های شما (NTP) دقیق باشد. قمر برای توالی زمانی به ساعت سیستم به‌شدت حساس است.
*   **مصرف بالای منابع:** اگر در محیط‌های با محدودیت رم هستید، تعداد `worker`ها را در فایل کانفیگ کاهش دهید.

برای دیباگ عمیق‌تر، از سوییچ `--verbose` استفاده کنید:
```bash
qamar start --verbose
```

## ۵. سوالات متداول (FAQ)

**آیا قمر برای پروژه‌های کوچک مناسب است؟**
بله، اتفاقاً معماری سبک آن باعث می‌شود که حتی روی یک Raspberry Pi هم به خوبی کار کند.

**آیا امکان ادغام با CI/CD وجود دارد؟**
قطعاً. قمر خروجی‌های استاندارد JSON دارد که می‌توانید به راحتی در خط لوله‌های Jenkins یا GitLab CI از آن‌ها استفاده کنید.

**آیا داده‌ها در دیسک ذخیره می‌شوند؟**
قمر اساساً یک لایه هماهنگ‌سازی است. ما پیشنهاد می‌کنیم برای ذخیره‌سازی داده‌های اصلی از پایگاه‌داده‌های معتبر استفاده کنید و قمر را برای مدیریت وضعیت (State Management) به کار ببرید.
