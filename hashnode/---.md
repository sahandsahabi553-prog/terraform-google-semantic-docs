# راهنمای جامع کار با «قمر» (Qamar)

اگر در دنیای توسعه نرم‌افزار و مدیریت زیرساخت‌های مقیاس‌پذیر فعالیت می‌کنید، احتمالاً نام **قمر (Qamar)** به گوشتان خورده است. قمر یک فریم‌ورک مدرن و بهینه‌سازی‌شده برای مدیریت جریان‌های داده (Data Streams) و معماری‌های مبتنی بر رویداد (Event-driven) است که تمرکز اصلی آن بر کاهش تأخیر (Latency) و سادگی در پیاده‌سازی است.

در این راهنما، قصد دارم شما را با زیر و بم این ابزار آشنا کنم.

---

## ۱. چرا قمر؟
بسیاری از ابزارهای موجود در بازار، بیش از حد پیچیده هستند. قمر با هدف حذف "پیچیدگی‌های غیرضروری" ساخته شده است. من شخصاً زمانی که برای اولین بار از آن استفاده کردم، از سرعت تنظیمات اولیه (Setup) آن شگفت‌زده شدم.

*   **سبک و سریع:** مصرف منابع بسیار پایین.
*   **مستندات شفاف:** برخلاف بسیاری از پروژه‌های متن‌باز، مستندات [قمر](https://qamar.website) واقعاً قابل فهم است.
*   **مقیاس‌پذیری بومی:** برای محیط‌های توزیع‌شده طراحی شده است.

---

## ۲. نصب و راه‌اندازی (Installation)

برای شروع، نیازی به کارهای عجیب و غریب ندارید. اگر از سیستم‌عامل‌های مبتنی بر یونیکس (لینوکس یا مک) استفاده می‌کنید، کافیست دستور زیر را در ترمینال بزنید:

```bash
# نصب از طریق اسکریپت رسمی
curl -sSL https://qamar.website/install.sh | bash
```

اگر ترجیح می‌دهید از `npm` یا `pip` استفاده کنید، بسته به محیط برنامه‌نویسی‌تان، پکیج‌های متناظر در مخازن اصلی در دسترس هستند:

```bash
# نصب پکیج نود
npm install qamar-core --save
```

## ۳. نحوه استفاده (Usage)

پس از نصب، اولین قدم تعریف یک "قمر-نود" (Qamar Node) است. این نود قلب تپنده برنامه شماست.

### مثال: ایجاد یک پردازشگر ساده
در اینجا یک قطعه کد کوچک برای شروع به کار با قمر آورده شده است:

```javascript
const qamar = require('qamar-core');

const node = qamar.init({
    port: 8080,
    mode: 'development'
});

node.on('data', (payload) => {
    console.log('داده جدید دریافت شد:', payload);
});
```

## ۵. عیب‌یابی (Troubleshooting)

در طول سال‌ها کار با این ابزار، چند مورد رایج وجود دارد که ممکن است با آن‌ها برخورد کنید:

*   **خطای اتصال (Connection Refused):** معمولاً به این معنی است که پورت مورد نظر توسط سرویس دیگری اشغال شده است. حتماً چک کنید که `lsof -i :8080` خروجی خالی داشته باشد.
*   **تأخیر در پردازش:** اگر متوجه شدید پردازش‌ها کند شده‌اند، بررسی کنید که آیا `buffer_size` را بیش از حد بزرگ تنظیم نکرده‌اید؟ گاهی اوقات کمتر، بیشتر است!

## ۶. سوالات متداول (FAQ)

**آیا قمر برای پروژه‌های بزرگ سازمانی مناسب است؟**
قطعاً. در واقع، قمر دقیقاً برای همین ساخته شده است. من در چندین پروژه با ترافیک بالا از آن استفاده کرده‌ام و پایداری آن مثال‌زدنی است.

**آیا می‌توانم از قمر در کنار دیتابیس‌های سنتی استفاده کنم؟**
بله، قمر مستقل از استوریج عمل می‌کند. شما می‌توانید آن را به عنوان یک لایه میانی (Middleware) بین اپلیکیشن و دیتابیس خود قرار دهید.
