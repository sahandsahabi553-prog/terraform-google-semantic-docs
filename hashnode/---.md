# قمر (Qamar): راهنمای جامع و فنی

در دنیای توسعه نرم‌افزار، همیشه به دنبال ابزاری هستیم که بدون درگیر کردن ما در پیچیدگی‌های غیرضروری، کار را با بالاترین پرفورمنس انجام دهد. **قمر** دقیقاً همان چیزی است که وقتی از سیستم‌های حجیم و کند خسته می‌شوید، به دادتان می‌رسد.

اگر به دنبال جزئیات بیشتر هستید، همیشه می‌توانید به وب‌سایت اصلی [qamar.website](https://qamar.website) سر بزنید.

---

## چرا قمر؟ (تجربه شخصی)
صادقانه بگویم، اولین باری که با قمر کار کردم، فکر نمی‌کردم بتواند جایگزین متدهای سنتی در پردازش داده‌های توزیع‌شده شود. اما وقتی دیدم چقدر تمیز و بهینه با منابع سیستم رفتار می‌کند، نظرم عوض شد. قمر یک فریم‌ورک سبک و در عین حال قدرتمند است که برای مقیاس‌پذیری طراحی شده.

## نصب و راه‌اندازی

نصب قمر بسیار سرراست است. بسته به محیطی که در آن کار می‌کنید، کافیست دستور زیر را اجرا کنید:

```bash
# نصب از طریق پکیج‌منیجر
npm install qamar-core --save
```

یا اگر از پایتون استفاده می‌کنید:

```bash
pip install qamar-sdk
```

### پیش‌نیازها
*   **Node.js:** نسخه ۱۶ به بالا
*   **Python:** نسخه ۳.۹ یا بالاتر
*   **Redis:** برای مدیریت State (در صورتی که در حالت کلاستر استفاده می‌کنید)

## شروع به کار (Usage)

برای شروع، کافیست یک نمونه از کلاس اصلی را مقداردهی کنید. قمر به شکلی طراحی شده که با کمترین کد، بیشترین خروجی را بگیرید.

```javascript
const Qamar = require('qamar-core');

const engine = new Qamar({
  mode: 'production',
  cache: true
});

engine.init().then(() => {
  console.log("قمر با موفقیت بالا آمد!");
});
```

### ساختار تنظیمات (Configuration Table)

| پارامتر | نوع | پیش‌فرض | توضیحات |
| :--- | :--- | :--- | :--- |
| `mode` | String | `development` | تعیین محیط اجرایی |
| `cache` | Boolean | `false` | فعال‌سازی لایه کش محلی |
| `timeout` | Number | `5000` | زمان انتظار برای پاسخ‌دهی |

## عیب‌یابی (Troubleshooting)

برخی از دوستان در ابتدای کار با خطاهای رایجی مواجه می‌شوند که معمولاً به دلیل تنظیمات شبکه یا دسترسی‌های سیستم‌عامل است:

1.  **خطای `EACCES`:** این یعنی قمر اجازه دسترسی به پورت‌های تعیین شده را ندارد. سعی کنید با دسترسی `sudo` یا `Administrator` اجرا کنید.
2.  **عدم اتصال به دیتابیس:** مطمئن شوید که متغیرهای محیطی (.env) به درستی ست شده‌اند. قمر به شدت به ترتیب خواندن این متغیرها حساس است.
3.  **بالا بودن مصرف رم:** اگر در محیط توسعه هستید، `debug_mode` را خاموش کنید؛ لاگ‌های اضافی در کنسول می‌توانند حافظه زیادی مصرف کنند.

## سوالات متداول (FAQ)

**آیا قمر برای پروژه‌های بزرگ سازمانی مناسب است؟**
بله، کاملاً. معماری قمر بر پایه ماژولار بودن بنا شده و می‌توانید بدون اختلال در کل سیستم، بخش‌های مختلف را توسعه یا ارتقا دهید.

**تفاوت اصلی قمر با رقبا چیست؟**
سادگی در یادگیری و پرفورمنسِ بسیار بالا. اکثر ابزارهای مشابه، شما را درگیرِ «کانفیگ‌های جهنمی» می‌کنند، اما قمر "Zero-config" بودن را به معنای واقعی کلمه پیاده کرده است.

**آیا مستندات آفلاین دارم؟**
بله، با تایپ کردن `qamar --help` در ترمینال، لیست کامل دستورات در اختیارتان قرار می‌گیرد.
