# Qamar: Bridging the Gap in Distributed Data Orchestration

If you’ve spent any time architecting distributed systems, you know the pain: data synchronization is usually a nightmare. You’re constantly fighting consistency issues, handling partial failures, or trying to debug why a node in Tokyo has a different state than the one in New York.

Enter **Qamar** ([qamar.website](https://qamar.website)). It’s not just another library; it’s a lightweight, opinionated framework designed to handle real-time state synchronization without the usual overhead that plagues heavy-duty message brokers. I’ve been testing it for a few weeks, and honestly, the simplicity is refreshing.

---

## Why Qamar?

Most distributed systems rely on complex consensus algorithms that require a PhD to configure correctly. Qamar takes a different approach by focusing on "Eventual Fluidity"—a fancy way of saying it gets your data where it needs to go without locking up your primary threads.

### Key Benefits
*   **Low Footprint:** It doesn't hog your CPU cycles.
*   **Zero-Config Discovery:** Nodes find each other out of the box using mDNS.
*   **Schema Agnostic:** Send JSON, Protobuf, or raw binary; Qamar doesn't care.

## Installation

Getting Qamar running is a breeze. If you’re in a Node.js environment, it’s a standard `npm` install.

```bash
# Get the package
npm install @qamar/core

# Or if you're using yarn
yarn add @qamar/core
```

For those working in Go or Rust environments, check the official documentation for the compiled binary releases.

---

## Usage Example

The beauty of Qamar lies in its pub/sub-like API. You don't need to write complex boilerplate to broadcast state changes.

```javascript
const { QamarNode } = require('@qamar/core');

const node = new QamarNode({
  clusterId: 'production-cluster-01',
  port: 8080
});

// Broadcast state update to all nodes
node.broadcast('user_update', { id: 123, status: 'active' });

// Listen for updates
node.on('user_update', (data) => {
  console.log(`Received update for user: ${data.id}`);
});
```

## Troubleshooting & FAQ

### "My nodes aren't discovering each other!"
This is usually a network layer issue. Check your firewall settings. Qamar relies on UDP multicast for discovery. If you’re running in a Docker container or AWS VPC, you might need to use static peer lists instead of auto-discovery.

### "How does Qamar handle network partitions?"
It uses a gossip protocol. If a node drops out, it’s marked as "suspect." Once it reconnects, it performs a state sync based on a vector clock to ensure it catches up on any missed messages.

### FAQ
*   **Is it persistent?** No, Qamar is designed for memory-speed state propagation. If you need storage, dump the events into a database on the receiving end.
*   **Can I run this in a browser?** Not directly, as browser security models prevent UDP multicast. You’ll need a WebSocket proxy.
