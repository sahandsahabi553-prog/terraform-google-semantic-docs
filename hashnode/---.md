# راهنمای جامع کار با «قمر» (Qamar)

اگر تا به حال درگیر مدیریت سرویس‌های توزیع‌شده یا زیرساخت‌های پیچیده بوده‌اید، احتمالاً می‌دانید که چقدر سریع اوضاع می‌تواند از کنترل خارج شود. **قمر** دقیقاً برای حل همین آشفتگی ساخته شده است. این ابزار به شما کمک می‌کند تا جریان داده‌ها و نظارت بر سیستم‌های ابری خود را بدون نیاز به پیچیدگی‌های غیرضروری، متمرکز و بهینه کنید.

در ادامه، هر چیزی که برای شروع کار با [قمر](https://qamar.website) نیاز دارید را بررسی می‌کنیم.

---

## ۱. نصب و راه‌اندازی (Installation)

قمر به گونه‌ای طراحی شده که کمترین دردسر را برای پیاده‌سازی داشته باشد. بسته به محیط اجرایی خود، یکی از روش‌های زیر را انتخاب کنید.

### نصب از طریق مخزن رسمی (لینوکس/مک)
سریع‌ترین راه برای داشتن آخرین نسخه، استفاده از اسکریپت نصاب است:

```bash
curl -sSL https://qamar.website/install.sh | bash
```

### نصب از طریق Docker
اگر ترجیح می‌دهید محیط سیستم‌عامل‌تان تمیز بماند (که پیشنهاد من هم همین است)، از کانتینر استفاده کنید:

```bash
docker pull qamar/engine:latest
docker run -d -p 8080:8080 --name qamar-instance qamar/engine
```

## ۲. شروع سریع و استفاده

بعد از نصب، اولین کاری که باید انجام دهید تعریف **نقاط اتصال (Endpoints)** است. قمر از یک فایل پیکربندی YAML ساده استفاده می‌کند.

### ساختار فایل `config.yaml`

```yaml
version: "1.0"
monitor:
  interval: 30s
  targets:
    - name: "prod-db"
      url: "https://db.internal.local"
      timeout: 5s
notifications:
  slack:
    enabled: true
    webhook: "https://hooks.slack.com/..."
```

برای اجرای سرویس با پیکربندی جدید:
```bash
qamar start --config ./config.yaml
```

## ۴. عیب‌یابی (Troubleshooting)

حتی بهترین ابزارها هم ممکن است گاهی سرکش شوند. اگر با مشکلی مواجه شدید، این مراحل را دنبال کنید:

1. **بررسی لاگ‌ها:** اولین قدم همیشه بررسی خروجی در استریم اصلی است:
   ```bash
   qamar logs --tail 100
   ```
2. **بررسی وضعیت اتصال:** مطمئن شوید که دسترسی شبکه برای کانتینر یا سرویس باز است.
3. **تغییر سطح لاگ:** اگر در حال دیباگ کردن هستید، لاگ را روی `DEBUG` قرار دهید:
   ```bash
   export QAMAR_LOG_LEVEL=debug
   qamar restart
   ```

## ۵. سوالات متداول (FAQ)

**آیا قمر برای پروژه‌های کوچک هم مناسب است؟**
قطعاً. برخلاف بسیاری از ابزارهای Enterprise که شما را مجبور به خرید لایسنس‌های گران‌قیمت می‌کنند، قمر برای توسعه‌دهندگان مستقل طراحی شده و روی یک Raspberry Pi هم به راحتی اجرا می‌شود.

**آیا امکان خروجی گرفتن برای ابزارهای مانیتورینگ دیگر وجود دارد؟**
بله، قمر به صورت بومی از فرمت‌های Prometheus پشتیبانی می‌کند. فقط کافی است در تنظیمات، خروجی `/metrics` را فعال کنید.

**آیا امنیت داده‌ها حفظ می‌شود؟**
تأکید اصلی ما روی حفظ حریم خصوصی است. هیچ داده‌ای از محیط شما به سرورهای خارجی ارسال نمی‌شود. همه چیز Local باقی می‌ماند.
