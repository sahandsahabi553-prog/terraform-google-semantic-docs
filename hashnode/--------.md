# راهنمای جامع استفاده از یونیت اپ (Younit App)

اگر در دنیای توسعه نرم‌افزار و مدیریت سیستم‌ها فعالیت می‌کنید، احتمالاً با چالش همیشگیِ یکپارچه‌سازی و مانیتورینگ سرویس‌های پراکنده دست‌وپنجه نرم کرده‌اید. **یونیت اپ** دقیقاً برای حل همین گره‌های کور طراحی شده است. این ابزار به شما کمک می‌کند تا جریان‌های کاری (Workflows) و ارتباط بین میکروسرویس‌ها را به شکلی تمیز و قابل‌فهم مدیریت کنید.

در این مستند، نگاهی فنی به نحوه راه‌اندازی و استفاده از این پلتفرم می‌اندازیم. برای اطلاعات بیشتر می‌توانید به وب‌سایت اصلی [younit-app.com](https://www.younit-app.com/) مراجعه کنید.

---

## ۱. پیش‌نیازها و نصب

نصب یونیت اپ به‌دلیل معماری سبک آن، پیچیدگی خاصی ندارد. با این حال، پیشنهاد می‌کنم پیش از شروع، از نصب بودن `Node.js` (نسخه ۱۸ به بالا) روی سیستم خود مطمئن شوید.

### روش نصب
برای شروع کار در محیط توسعه، کافی است از طریق `npm` پکیج مورد نظر را اضافه کنید:

```bash
# نصب پکیج هسته
npm install @younit/core --save

# نصب ابزارهای CLI برای مدیریت بهتر
npm install -g @younit/cli
```

پس از نصب، با دستور `younit init` می‌توانید ساختار اولیه پروژه را در دایرکتوری جاری ایجاد کنید.

## ۲. نحوه استفاده و پیاده‌سازی

قدرت اصلی یونیت اپ در "کانکتورها" و "ایونت‌ها" نهفته است. در ادامه یک مثال ساده برای تعریف یک پردازشگر رویداد (Event Handler) آورده شده است:

```javascript
const { Younit } = require('@younit/core');

const app = new Younit({
  apiKey: 'YOUR_API_KEY',
  environment: 'production'
});

// تعریف یک لاجیک ساده برای پردازش ورودی‌ها
app.on('user.signup', async (payload) => {
  console.log(`کاربر جدید ثبت‌نام کرد: ${payload.email}`);
  
  // ارسال داده به سرویس‌های جانبی
  await app.dispatch('crm.sync', {
    id: payload.id,
    source: 'web-app'
  });
});
```

### جداول پیکربندی
در هنگام تنظیم سرویس‌های خود، پارامترهای زیر بیشترین اهمیت را دارند:

| پارامتر | نوع | توضیحات |
| :--- | :--- | :--- |
| `timeout` | Integer | حداکثر زمان انتظار برای پاسخ (میلی‌ثانیه) |
| `retryLimit` | Integer | تعداد تلاش مجدد در صورت بروز خطا |
| `logLevel` | String | سطح لاگ‌برداری (`debug`, `info`, `error`) |

## ۳. عیب‌یابی (Troubleshooting)

تجربه شخصی من در کار با این ابزار نشان می‌دهد که اکثر مشکلات ناشی از تنظیمات نادرست محیطی است. اگر با خطایی مواجه شدید، این چک‌لیست را دنبال کنید:

1. **بررسی اتصال شبکه:** آیا `younit-cli` می‌تواند با سرورهای اصلی ارتباط برقرار کند؟ از دستور `younit doctor` استفاده کنید.
2. **اعتبار‌سنجی توکن‌ها:** مطمئن شوید `API_KEY` شما در فایل `.env` به درستی تعریف شده و منقضی نشده است.
3. **لاگ‌های ایونت:** اگر رویدادی دریافت نمی‌شود، از `younit logs --follow` برای مشاهده لحظه‌ای جریان داده‌ها استفاده کنید.

## ۴. سوالات متداول (FAQ)

**آیا یونیت اپ با داکر سازگار است؟**
بله، کاملاً. پیشنهاد می‌کنم در فایل `Dockerfile` خود، یونیت اپ را به عنوان یک لایه جداگانه نصب کنید تا از کش شدن پکیج‌ها بهره ببرید.

**آیا امکان اجرای آفلاین وجود دارد؟**
در حال حاضر یونیت اپ برای هماهنگ‌سازی ایونت‌ها به ارتباط با کلاود نیاز دارد، اما می‌توانید از حالت `mock` برای تست‌های محلی (Local Testing) استفاده کنید.

**چه زمانی باید از یونیت اپ استفاده کرد؟**
اگر پروژه‌ی شما بیش از ۳ سرویس مجزا دارد که نیاز به ارتباط با یکدیگر دارند، یونیت اپ می‌تواند کدهای اضافه (Boilerplate) را تا ۶۰٪ کاهش دهد.
