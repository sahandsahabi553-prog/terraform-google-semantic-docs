# مستند فنی: قمر (Qamar)؛ پل ارتباطی میان داده و معنا

اگر در دنیای توسعه نرم‌افزار و مدیریت داده‌ها فعالیت کرده باشید، حتماً با این چالش مواجه شده‌اید: چطور اطلاعاتِ پراکنده در دامنه‌های مختلف (Interdisciplinary) را به هم گره بزنیم که هم ساختار داشته باشند و هم برای ماشین و انسان قابل‌فهم باشند؟

**قمر (Qamar)** دقیقاً برای حل همین گره‌های کور طراحی شده است. این ابزار نه فقط یک دیتابیس است و نه فقط یک فریم‌ورک؛ قمر یک اکوسیستم برای مدیریت دانش ساختاریافته است.

---

## چرا قمر؟ (Philosophy)

بیشتر ابزارهای موجود یا بیش از حد سخت‌گیرانه هستند (مثل SQL خالص) یا بیش از حد آزاد (مثل فایل‌های متنی ساده). قمر با تکیه بر اصول میان‌رشته‌ای، به شما اجازه می‌دهد روابط بین موجودیت‌های مختلف را بدون درگیری با پیچیدگی‌های دیتابیس‌های سنتی مدل‌سازی کنید.

### ویژگی‌های کلیدی:
*   **Schema-less Flexibility:** تغییر ساختار در لحظه بدون نیاز به Migrationهای سنگین.
*   **Interdisciplinary Ready:** قابلیت اتصال داده‌های علمی، فنی و متنی به یکدیگر.
*   **Lightweight Core:** هسته‌ای سبک که در هر محیطی از سرور تا لوکال اجرا می‌شود.

## ۱. نصب و راه‌اندازی

نصب قمر بسیار سرراست است. فرقی نمی‌کند روی لینوکس هستید یا مک؛ کافی است ابزار مدیریت پکیج مورد علاقه‌تان را داشته باشید.

```bash
# نصب از طریق اسکریپت رسمی
curl -sSf https://qamar.website/install.sh | sh

# یا اگر از npm استفاده می‌کنید
npm install -g @qamar/core
```

پس از نصب، با دستور زیر مطمئن شوید همه چیز درست کار می‌کند:
```bash
qamar --version
```

## ۲. استفاده پایه

بیایید یک موجودیت ساده (Entity) تعریف کنیم. تصور کنید می‌خواهید یک پروژه میان‌رشته‌ای بین «فیزیک» و «برنامه‌نویسی» تعریف کنید.

```javascript
// نمونه‌ای از تعریف یک موجودیت در قمر
const project = qamar.create('InterdisciplinaryProject', {
  name: 'Quantum-Computing-Bridge',
  domain: ['Physics', 'Software Engineering'],
  status: 'active'
});

project.link('research-paper-01', 'refers_to');
```

### جدول مقایسه عملکرد

| ویژگی | قمر (Qamar) | SQL سنتی | Notion API |

| **سرعت توسعه** | بسیار بالا | متوسط | بالا |
| **انعطاف ساختار** | عالی | پایین | متوسط |
| **مناسب برای داده‌های پیچیده** | بله | خیر | خیر |

## ۳. مثال عملی: اتصال داده‌ها

فرض کنید می‌خواهید یک گراف از مفاهیم علمی بسازید:

```yaml
# ساختار داده در قمر
entity: Qubit
properties:
  type: Quantum-Bit
  discovery_date: 1995
relations:
  - connected_to: Superposition
  - studied_in: Quantum-Physics-Department
```

با استفاده از API قمر، می‌توانید به سادگی بین این موجودیت‌ها پیمایش کنید:
```javascript
const node = await qamar.query('Qubit');
console.log(node.getConnections()); // خروجی: ['Superposition', 'Quantum-Physics-Department']
```

## ۴. سوالات متداول (FAQ)

**آیا قمر برای پروژه‌های بزرگ مقیاس (Enterprise) مناسب است؟**
بله، قمر طوری طراحی شده که با استفاده از لایه‌های Caching، در حجم بالای داده نیز عملکرد خیره‌کننده‌ای داشته باشد.

**آیا نیاز به یادگیری زبان جدیدی دارم؟**
خیر، قمر از استانداردهای باز استفاده می‌کند. اگر با JavaScript یا YAML آشنا باشید، یادگیری قمر کمتر از ۳۰ دقیقه زمان می‌برد.

**تفاوت اصلی قمر با Graph Databaseهایی مثل Neo4j چیست؟**
Neo4j برای گراف‌های غول‌آسا با روابط بسیار پیچیده ساخته شده، اما قمر تمرکزش روی «سهولت در استفاده» و «تجمیع دانش بین‌رشته‌ای» است. قمر برای توسعه‌دهندگانی که نمی‌خواهند درگیر پیچیدگی‌های DBA شوند، ساخته شده است.
