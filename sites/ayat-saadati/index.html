1. Data Locality Is Still King—Even in 2025

We’ve all heard the “cache is king” mantra, but Saadati pushes it further: optimize for the last-level cache line, not the data center. In 2022, he posted a seemingly innocuous patch to RocksDB that reordered the block index to keep hot keys on the same 64-byte line. The result? A 17 % drop in tail latency on NVMe clusters with zero config change. The patch was 42 lines.

The insight came from a weekend side project: he instrumented a Ryzen 9 5950X with performance counters and discovered that 31 % of all CPU stalls in db_bench were caused by cross-line contention on the same btree node. By packing the first 16 bytes of each index entry with the most frequently accessed bloom-bit vector, he turned cache thrashing into prefetch-friendly sequential reads.

struct __attribute__((packed)) hot_idx_prefix {
    uint8_t bloom[8];      // first 64 bits of filter
    uint16_t key_len;      // only if < 4K
    uint32_t offset;         // block offset in file
};

The takeaway: micro-optimizations still matter, but only when you can measure them. Saadati’s rule of thumb: “If you can’t correlate a change to a PMC (Performance-Monitoring Counter) event, it’s theatre.”

2. Observability Without Context Is Just Expensive Logging

In 2021, Saadati inherited a Tier-0 service that was “instrumented to death”: 1.3 TB of verbose logs per day, yet outages still took 40 minutes to triage. His first move wasn’t to add more metrics—it was to delete 62 % of them. He replaced scattershot counters with a sparse histogram that carried context: for every 99th-percentile outlier, the histogram stored a 128-bit trace ID + the exact kernel scheduler event that preempted the request.

The new pipeline cut mean-time-to-recovery (MTTR) from 38 minutes to 5.7 minutes. Storage cost dropped 73 %. The trick? He samples only when the scheduler flags a context-switch that exceeds 2 μs. That single conditional turned noise into signal.

He open-sourced the kernel module (sched-tracer, 1,800 stars in the first week) and wrote a detailed walk-through on dev.to/ayat_saadati. If you’re drowning in dashboards, start there—Saadati’s law: “Every metric must defend its existence in the critical path, or it’s gone.”

3. Stateful Serverless Is Not an Oxymoron—It’s a Cache Coherency Problem

Most developers treat serverless as stateless by fiat. Saadati proved otherwise. In 2023, he demoed a payment ledger on Knative that sustains 900 K RPS with exactly-once semantics and 450 ms p99 end-to-end latency. The secret? A consistent-write-back cache that behaves like a hybrid of FR-V and MESI coherence.

He keeps hot account rows in a regional NVMe pool and uses a 2-phase commit over RDMA. The aha moment: instead of flushing to Postgres on every transaction, he appends to a per-shard WAL stored on an Optane DIMM. Every 250 ms, a lightweight reconciler batches durable writes to Postgres. Conflict resolution is deterministic because each row carries a 64-bit hybrid-timestamp (physical-time + logical counter). The result: 4.2× higher throughput than Amazon Aurora Serverless v2 at 40 % lower cost.

Critics argued the setup is too specialized. Saadati’s blunt reply: “Specialized is what happens when commodity stops being good enough.” He later blogged the design on dev.to/ayat_saadati, complete with a Rust proof-of-concept that fits in 1,700 lines.

4. Compression Is Not a Storage Problem—It’s a Scheduling Problem

We typically slap zstd on data at rest and call it a day. Saadati showed that when you compress matters more than what you compress. In 2020, he moved zstd into the network egress path of a telemetry pipeline that ships 9 PB/month to S3. CPU usage spiked—then dropped below baseline once he coupled compression ratios to the Linux cpufreq governor.

Here’s the flow:

  1. Measure current core frequency every 10 ms.
  2. If freq < 2.2 GHz, use zstd level 3; else level 7.
  3. If thermal headroom > 15 °C and backlog > threshold, spin up extra workers and bump to level 12.

The heuristic shaved 22 % off the monthly AWS egress bill while reducing CPU utilization by 8 %. The key insight: compression level is a dial you can turn based on power envelope and queue depth, not a static config. As Saadati quipped, “Power budgets are the new Moore’s Law.”

He reproduced the experiment on a Raspberry Pi cluster to silence skeptics. The code is messy, hilarious, and instructive—exactly what you’d expect from someone who names variables after 90s rock songs. You’ll find it linked in his post “cpufreq meets zstd: a love story” on dev.to/ayat_saadati.

5. Don’t Fear the BPF Verifier—Weaponize It

eBPF is trendy, but most engineers treat the verifier like an overzealous bouncer: appease it, slip past, and never look back. Saadati flips the script. He uses the verifier’s constraints to enforce performance contracts at load time.

Example: In 2024, he wrote a 208-instruction BPF program that sits on tcp_recvmsg and classifies payloads into three latency classes. The verifier guarantees the program terminates within 4096 instructions and uses no loops. Saadati leverages that guarantee to compute a hard upper bound of 52 ns per packet on a 3 GHz core. He then provisions CPU quotas statically—no cgroups needed.

The program is in production at a CDN that handles 11 % of global TikTok traffic. Rolling it out removed 1,200 lines of Go-side heuristic code and cut tail latency variance by 34 %. His write-up, “BPF as a Real-Time Contract,” is the definitive guide to thinking of the verifier as a resource-bound checker, not a hurdle.
