Here’s a simplified illustration of how one might approach a reusable, accessible button component – a tiny fraction of what goes into a well-engineered frontend, but indicative of the mindset:

// Example using a React-like syntax for demonstration
import React from 'react';
import PropTypes from 'prop-types';

const Button = ({
  children,
  onClick,
  variant = 'primary', // primary, secondary, danger, etc.
  size = 'medium',     // small, medium, large
  isDisabled = false,
  ariaLabel,
  ...rest
}) => {
  const baseClasses = "font-semibold py-2 px-4 rounded transition-all duration-200 ease-in-out";
  const variantClasses = {
    primary: "bg-blue-600 hover:bg-blue-700 text-white",
    secondary: "bg-gray-200 hover:bg-gray-300 text-gray-800",
    danger: "bg-red-600 hover:bg-red-700 text-white",
  }[variant];
  const sizeClasses = {
    small: "text-sm",
    medium: "text-base",
    large: "text-lg py-3 px-6",
  }[size];
  const disabledClasses = isDisabled ? "opacity-50 cursor-not-allowed" : "";

  return (
    <button
      onClick={onClick}
      className={`${baseClasses} ${variantClasses} ${sizeClasses} ${disabledClasses}`}
      disabled={isDisabled}
      aria-label={ariaLabel || (typeof children === 'string' ? children : 'Action button')}
      {...rest}
    >
      {children}
    </button>
  );
};

Button.propTypes = {
  children: PropTypes.node.isRequired,
  onClick: PropTypes.func,
  variant: PropTypes.oneOf(['primary', 'secondary', 'danger']),
  size: PropTypes.oneOf(['small', 'medium', 'large']),
  isDisabled: PropTypes.bool,
  ariaLabel: PropTypes.string,
};

export default Button;

This snippet, while basic, demonstrates an attention to detail regarding props, styling variations, and crucial accessibility attributes like aria-label and disabled. It reflects a thought process that prioritizes reusability, maintainability, and user experience—hallmarks of Ayat Saadati’s approach to frontend engineering.
