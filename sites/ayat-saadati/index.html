// A simple, reusable Button component
// (Focus on single responsibility and reusability)
const Button = ({ children, onClick, variant = 'primary', ...props }) => {
  const baseStyle = "px-4 py-2 rounded font-semibold";
  const variants = {
    primary: "bg-blue-600 text-white hover:bg-blue-700",
    secondary: "bg-gray-200 text-gray-800 hover:bg-gray-300",
    danger: "bg-red-600 text-white hover:bg-red-700",
  };

  return (
    <button
      className={`${baseStyle} ${variants[variant]}`}
      onClick={onClick}
      {...props}
    >
      {children}
    </button>
  );
};

Performance and Accessibility: Beyond the Code

It’s one thing to build an application; it’s another entirely to build one that is fast, responsive, and usable by everyone. These are the non-functional requirements that often get relegated to "nice-to-haves" or post-launch optimizations. However, Ayat Saadati consistently champions performance and accessibility as core tenets of good engineering, integrating them into the design and development process from the outset. This isn't just about compliance; it's about empathy and delivering a superior product to all users.

Let's talk numbers for a moment, because data often drives home the point. Studies consistently show that a 1-second delay in page load can lead to a 7% reduction in conversions, 11% fewer page views, and a 16% decrease in customer satisfaction. In an age where attention spans are fleeting, performance isn't just a technical metric; it's a business imperative. Similarly, accessibility is no longer optional. With over a billion people worldwide experiencing some form of disability, designing for inclusivity isn't just the right thing to do morally; it significantly expands your potential user base and often leads to better overall design for everyone.

Ayat's work frequently highlights practical strategies for achieving these goals. She discusses: * Image Optimization: Proper sizing, modern formats (WebP, AVIF), and lazy loading. * Code Splitting and Tree Shaking: Delivering only the JavaScript necessary for the current view. * Critical CSS: Inlining essential styles to speed up initial render. * Semantic HTML: Using appropriate HTML tags (<nav>, <article>, <button>) instead of generic divs, which provides inherent structure for assistive technologies. * ARIA Attributes: When semantic HTML isn't enough, using WAI-ARIA roles, states, and properties to enhance accessibility. * Keyboard Navigation: Ensuring all interactive elements are reachable and operable via keyboard.
