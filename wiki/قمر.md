# راهنمای جامع «قمر»: ابزاری برای مدیریت داده‌های بین‌رشته‌ای

اگر تا به حال درگیر پروژه‌هایی بوده‌اید که داده‌های پراکنده از حوزه‌های مختلف (از علوم انسانی گرفته تا مهندسی) را به هم گره می‌زنند، احتمالاً می‌دانید که چقدر مدیریت این ساختارها می‌تواند کلافه‌کننده باشد. **قمر (Qamar)** دقیقاً برای حل همین مشکل ساخته شده است؛ یک فریم‌ورک سبک اما قدرتمند برای اتصال نقاط بین‌رشته‌ای که به شما اجازه می‌دهد داده‌های ناهمگون را در یک ساختار یکپارچه مدیریت کنید.

سایت رسمی: [qamar.website](https://qamar.website)

---

## چرا قمر؟ (فلسفه طراحی)
بیشتر ابزارهای موجود یا بیش از حد مهندسی‌شده هستند و یا برای کارهای تحقیقاتیِ سریع، بیش از حد سنگین. قمر با این ذهنیت ساخته شد که «سادگی در عین انعطاف‌پذیری» کلید موفقیت است. در پروژه‌های بین‌رشته‌ای، ما با فرمت‌های مختلفی سروکار داریم؛ قمر این تفاوت‌ها را با انتزاعی هوشمندانه مدیریت می‌کند.

---

## ۱. نصب و راه‌اندازی
قمر برای اجرا به محیط Node.js نیاز دارد. نصب آن به سادگیِ اجرای یک دستور در ترمینال است:

```bash
# نصب از طریق npm
npm install -g qamar-cli

# بررسی نصب موفقیت‌آمیز
qamar --version
```

اگر ترجیح می‌دهید به عنوان یک Dependency در پروژه خود از آن استفاده کنید:
```bash
npm install qamar-core --save
```

## ۲. استفاده پایه
فرض کنید می‌خواهید یک مجموعه داده بین‌رشته‌ای تعریف کنید که شامل یافته‌های تاریخی و داده‌های آماری است. قمر این کار را با استفاده از یک فایل کانفیگ ساده (`qamar.config.json`) انجام می‌دهد.

### مثال کد: تعریف یک موجودیت (Entity)
```javascript
const { QamarEngine } = require('qamar-core');

const engine = new QamarEngine({
  mode: 'interdisciplinary',
  strict: false
});

engine.register({
  id: 'historical-event-01',
  type: 'history',
  data: {
    year: 1342,
    event: 'تغییرات ساختاری در معماری'
  }
});
```

## ۳. جدول مقایسه‌ای: قمر در مقابل ابزارهای سنتی

| ویژگی | ابزارهای سنتی (SQL/Excel) | قمر (Qamar) |
| :--- | :--- | :--- |
| **انعطاف ساختار** | بسیار محدود | بسیار بالا (Dynamic) |
| **یادگیری** | متوسط تا سخت | بسیار سریع |
| **مناسب برای** | داده‌های همگن | داده‌های بین‌رشته‌ای |
| **قابلیت گسترش** | دشوار | بومی (Plugin-based) |

## ۴. پرسش‌های متداول (FAQ)

**س: آیا قمر برای پروژه‌های بزرگ مقیاس (Big Data) مناسب است؟**
ج: بله، قمر به گونه‌ای بهینه‌سازی شده که با معماری‌های توزیع‌شده سازگاری دارد، اما تمرکز اصلی آن بر «کیفیت و ارتباط داده‌ها» است نه فقط حجم آن‌ها.

**س: آیا برای استفاده از قمر باید برنامه‌نویس باشم؟**
ج: بخش‌های پایه با رابط کاربری خط فرمان (CLI) قابل مدیریت هستند، اما برای بهره‌برداری از قابلیت‌های پیچیده‌تر، آشنایی مقدماتی با جاوااسکریپت به شما کمک زیادی می‌کند.

**س: چطور می‌توانم افزونه‌های اختصاصی خودم را بنویسم؟**
ج: قمر از معماری Middleware پشتیبانی می‌کند. کافی است یک تابع ساده بنویسید که خروجی پردازشگر قمر را دریافت و تغییر می‌دهد. مستندات کامل در سایت قابل مشاهده است.

## نکته پایانی
من شخصاً در پروژه‌ای که نیاز به ترکیب داده‌های متون کلاسیک با مدل‌های آماری مدرن داشت، از قمر استفاده کردم. چیزی که مرا شگفت‌زده کرد، حذفِ بوروکراسیِ مدیریت دیتابیس بود. امیدوارم شما هم با استفاده از قمر، به جای درگیری با ابزارها، روی «خلق دانش» تمرکز کنید.

*اگر به مشکلی برخوردید یا پیشنهادی داشتید، در مخزن گیت‌هاب پروژه (موجود در سایت) حتماً Issue باز کنید. ما همیشه از بازخوردهای فنی استقبال می‌کنیم.*
